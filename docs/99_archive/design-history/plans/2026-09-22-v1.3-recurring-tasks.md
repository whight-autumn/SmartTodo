# SmartTodo V1.3 Recurring Tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add dependable daily, weekly, monthly, and yearly recurring tasks with 04:00 cycle rollover, missed-cycle carryovers, reusable reminders, responsive UI, and a non-wrapping brightness percentage, then ship and push SmartTodo V1.3.0.

**Architecture:** Keep each recurring root task on a stable ID and add a pure local-calendar recurrence module. `task-model.js` owns task normalization and idempotent rollover, while `app.js` owns persistence, 04:00 scheduling, notification deduplication, rendering, and the authoritative widget write path. Missed occurrences are represented by one-time system child tasks, with multiple offline periods consolidated into one child.

**Tech Stack:** Electron 31, browser JavaScript, CommonJS/UMD modules, HTML/CSS, `node:test`, Electron integration tests, electron-builder.

**Spec:** `docs/superpowers/specs/2026-09-22-v1.3-recurring-tasks-design.md`

## Global Constraints

- Target version is exactly `1.3.0`, displayed as `V1.3.0`.
- Existing tasks without recurrence data remain one-time tasks without destructive migration.
- Recurrence types are exactly `none`, `daily`, `weekly`, `monthly`, and `yearly`.
- Logical boundaries are daily 04:00, Monday 04:00, month day 1 at 04:00, and January 1 at 04:00 in local time.
- A recurring task must have a valid reminder timestamp before it can be created.
- Only root tasks own recurrence; user-created subtasks reset with their recurring root.
- The stable recurring root retains title, remarks, attachments, priority, pinned state, and ID.
- A missed occurrence creates one non-recurring system child; consecutive offline misses are consolidated with an exact count and range.
- The initial reminder is the immutable calendar anchor; month-end and leap-year clamping must not drift the anchor.
- The app does not introduce a Windows service and does not promise notification delivery while fully exited.
- Main renderer remains the only task-state writer; widget completion continues through the existing validated IPC path.
- No new runtime dependency is added.
- UI must remain usable from 800×620 upward and in the existing 100%/125%/150% zoom matrix.
- Existing `smart_tasks`, attachment directories, AI settings, chat data, and widget preferences remain compatible.
- Executables remain ignored by Git and are delivered through local output/GitHub Releases rather than committed to the repository.

## Review Focus

- A reminder before 04:00 must belong to the previous logical cycle, not the civil date displayed by the clock; Task 2 pins Monday 02:00/04:00 behavior.
- A first reminder set in a future cycle must not roll forward at the intervening boundary; Task 3 tests a future `activeCycleKey`.
- Restarting repeatedly in the same cycle must never duplicate a carryover; Task 3 runs rollover twice and compares task IDs.
- Long offline gaps must distinguish a previously completed occurrence from implicitly missed intermediate cycles; Task 3 tests both completed and unfinished roots across three periods.
- January 31 and February 29 reminders must clamp temporarily and later recover their original anchor day; Task 2 tests both recovery sequences.

- [ ] **Step 3: Implement the UMD recurrence module**

Use this public shell and immutable-anchor rule:

```js
(function exposeRecurrenceModel(root, factory) {
  const api = factory();
  if (typeof module !== "undefined" && module.exports) module.exports = api;
  else root.RecurrenceModel = api;
})(typeof globalThis !== "undefined" ? globalThis : this, function createRecurrenceModel() {
  const TYPES = new Set(["none", "daily", "weekly", "monthly", "yearly"]);
  const BOUNDARY_HOUR = 4;

  function normalizeType(value) {
    return TYPES.has(value) ? value : "none";
  }

  function getCycleKey(type, at) {
    const normalizedType = normalizeType(type);
    if (normalizedType === "none") return "";
    const shifted = new Date(at);
    if (!Number.isFinite(shifted.getTime())) return "";
    shifted.setHours(shifted.getHours() - BOUNDARY_HOUR);
    const year = shifted.getFullYear();
    const month = String(shifted.getMonth() + 1).padStart(2, "0");
    const day = String(shifted.getDate()).padStart(2, "0");
    if (normalizedType === "daily") return `D:${year}-${month}-${day}`;
    if (normalizedType === "monthly") return `M:${year}-${month}`;
    if (normalizedType === "yearly") return `Y:${year}`;
    const monday = new Date(year, shifted.getMonth(), shifted.getDate());
    monday.setDate(monday.getDate() - ((monday.getDay() + 6) % 7));
    return `W:${monday.getFullYear()}-${String(monday.getMonth() + 1).padStart(2, "0")}-${String(monday.getDate()).padStart(2, "0")}`;
  }

  function getOccurrenceReminder(value, cycleKey) {
    const item = normalizeRecurrence(value);
    const distance = getCycleDistance(item.type, getCycleKey(item.type, item.anchorAt), cycleKey);
    const anchor = new Date(item.anchorAt);
    return addCalendarPeriodsFromAnchor(anchor, item.type, distance).toISOString();
  }

  return {
    BOUNDARY_HOUR,
    normalizeRecurrence,
    createRecurrence,
    getCycleKey,
    getCycleDistance,
    offsetCycleKey,
    getOccurrenceReminder,
    formatRecurrenceLabel,
    getReminderFingerprint,
    getNextDailyBoundary
  };
});
```

Use `Date.UTC(year, month, day)` only for counting calendar-day distance; construct reminder timestamps with local `new Date(year, month, day, hour, minute)` so reminders stay at the selected wall-clock time.

`addCalendarPeriodsFromAnchor()` must read the anchor's original local day before changing year/month. For monthly/yearly targets, compute the target month's last day with `new Date(targetYear, targetMonth + 1, 0).getDate()`, then use `Math.min(anchorDay, lastDay)`; never use a previously clamped occurrence as the next anchor.
