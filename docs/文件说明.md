# 文件说明 · 智能任务管家

> 本文档说明仓库内**每一份代码文件**的职责，帮助新使用者快速定位功能模块。
> 项目为 Electron 桌面应用，采用经典三层结构：主进程（Node.js）、preload 桥接、渲染进程（HTML/CSS/原生 JS）。
> 当前文档版本：V1.0.7（2026-09-15）。功能、文件名或发布结构发生变化时应同步更新本文档。

---

## 一、根目录

| 文件 | 职责 |
| --- | --- |
| `main.js` | **Electron 主进程入口**。创建主窗口、系统托盘与右键菜单；处理「关闭窗口不退出、驻留托盘」逻辑；注册原生通知、版本号、运行数据路径接口；初始化受管任务附件存储及固定 IPC；启动时迁移旧版本运行数据；单实例锁防止重复启动。 |
| `main-paths.js` | 集中定义 `buildManagedUserDataPath` 与 `buildTaskAttachmentPath` 两个纯函数，分别拼接 `%APPDATA%\智能任务管家\运行数据` 和其中的 `task-attachments` 附件根目录，便于主进程引用与单元测试。 |
| `task-attachment-store.js` | **任务附件存储模块**。将用户选择的文件复制到 `运行数据\task-attachments\<任务ID>\` 的最终位置；按任务串行导入、提交清理、回滚、启动协调和整目录清理，依据目录实际条目独立执行 10 个限制；固定受管根目录的规范路径与文件身份，拒绝符号链接、联接、非目录替换、非普通文件和路径逃逸。准备阶段不移动旧文件，回滚只删除本次导入；持久化后提交尽力删除旧文件并始终释放事务状态，启动协调会幂等清理未被规范化元数据引用的受管文件。 |
| `task-attachment-ipc.js` | **附件 IPC 安全边界**。只注册固定的附件准备、提交、回滚、启动协调、目录清理、解析、打开和外链通道，严格校验 payload、任务 ID、事务 ID、存储名、引用列表和任务 ID 列表；通过存储模块解析文件后调用系统打开，并仅允许 `http:` / `https:` 外链交给默认浏览器。 |
| `preload.js` | **preload 桥接脚本**。通过 `contextBridge` 暴露最小 `window.desktop` 对象；附件准备方法只接收文件选择框产生的 `File`，在隔离上下文内调用 `webUtils.getPathForFile` 并拒绝伪造、非 `File` 或空路径输入；另暴露固定提交、回滚、启动协调、目录清理、地址解析、附件打开和安全外链包装。不暴露路径转换函数、任意绝对路径导入、`ipcRenderer`、文件系统或任意通道。 |
| `package.json` | 项目元数据与脚本。声明 Electron / electron-builder 依赖；定义 `start`（运行）、`test`（单元测试）、`test:ui`（界面冒烟测试）、`dist`（打包 Windows 便携版）等命令；内含 electron-builder 打包配置。 |
| `package-lock.json` | 锁定依赖版本，确保 `npm install` 安装结果一致。勿手动编辑。 |
| `README.md` | 项目介绍、功能特性、快速开始、项目结构与发布说明。 |
| `.gitignore` | Git 忽略规则：排除 `node_modules/`、构建产物、`*.exe` 等不应入库的内容。 |

## 二、renderer/ 渲染进程（界面与业务逻辑）

| 文件 | 职责 |
| --- | --- |
| `index.html` | 应用唯一页面。包含任务待办、AI 助手、可重复打开的任务备注/附件编辑弹窗、设置与删除确认弹窗等界面骨架；按顺序引入 6 个渲染脚本。 |
| `style.css` | 全部界面样式：深浅两套主题、竹青/墨色/绛红/靛蓝/淡金配色、亮度混合变量、任务卡片、备注链接、附件缩略图与状态、编辑弹窗、聊天框和响应式布局。 |
| `app.js` | **渲染进程主逻辑**。负责任务增删改查、子任务挂载、优先级排序、置顶、折叠、完成/撤销、三类筛选与计数、15 天清理、提醒、AI 会话、主题/亮度、草稿及版本显示；并管理可重复备注编辑草稿、已保存/待保存图片的惰性预览及 object URL 回收、文件 MIME/类型、附件可用性与缺失提示、安全链接/附件打开和附件事务保存。先持久化引用最终文件的下一份任务快照，再提交旧文件清理；写入失败时只回滚本次导入，清理警告保持弹窗打开并恢复控件，启动时按当前元数据请求协调受管目录。 |
| `task-model.js` | **任务纯逻辑模块**（可被 `node:test` 直接测试）。除排序、父子索引、完成/撤销、过期清理和筛选外，还规范化 `updatedAt` 与附件元数据，并通过 `applyTaskNoteEdit` 只在备注或附件实际变化时更新时间，保持 `createdAt` / `completedAt` 不变。 |
| `draft-store.js` | **任务表单草稿模块**。在输入变化/窗口隐藏时保存未提交的表单内容（标题、备注、提醒、优先级、父任务），页面重新打开后可恢复。兼容 `localStorage` 与 Map 等存储实现。 |
| `ai-provider.js` | **AI 协议适配模块**。封装 OpenAI-compatible Chat Completions：DeepSeek/OpenAI/自定义三套预设（`PROVIDER_PRESETS`）、配置规范化、`/chat/completions` 地址拼接、SSE 流式增量解析（`parseSseChunk`）。挂载为 `window.AIProvider` 并支持 `module.exports`。 |
| `ui-appearance.js` | **界面外观纯逻辑模块**。管理 75%–125% 亮度滑杆的归一化、存储与读写（`normalizeBrightness` / `resolveBrightness` / `loadBrightness` / `saveBrightness`），以及任务时间戳格式化（`formatTaskTimestamp`）。 |
| `note-utils.js` | **备注安全渲染模块**。先转义纯文本，再识别并生成可委托打开的 HTTP/HTTPS 链接，处理换行和中英文尾随标点；其他协议不会变成链接。兼容浏览器与 `module.exports`。 |

## 模块间调用关系

```
main.js ──require──▶ main-paths.js              （运行数据/附件路径）
main.js ──require──▶ task-attachment-store.js   （受管附件文件操作）
main.js ──require──▶ task-attachment-ipc.js     （固定 IPC / 协议校验）
main.js ──preload──▶ preload.js                 （contextBridge 最小桥接）
                          │
renderer/index.html ◀── window.desktop    （渲染进程通过 IPC 调用原生能力）
renderer/index.html ──引入──▶ app.js
app.js ──window.TaskModel──▶ task-model.js     （任务纯逻辑）
app.js ──window.DraftStore──▶ draft-store.js   （表单草稿）
app.js ──window.AIProvider──▶ ai-provider.js   （AI 协议适配）
app.js ──window.UIAppearance──▶ ui-appearance.js（外观/亮度）
app.js ──window.NoteUtils──▶ note-utils.js       （备注转义/安全链接）
tests/*.test.js ──require──▶ renderer/*.js      （纯逻辑模块可直接单测）
tests/*.test.js ──require──▶ 附件 store / IPC   （主进程边界可独立单测）
```

> 说明：`task-model.js`、`draft-store.js`、`ai-provider.js`、`ui-appearance.js`、`note-utils.js` 采用「UMD 风格」——浏览器环境下挂载到 `window`，Node 环境下通过 `module.exports` 导出，因此既能被页面直接使用，也能被 `node:test` 单元测试加载。
