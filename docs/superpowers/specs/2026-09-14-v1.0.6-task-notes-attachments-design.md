# 智能任务管家 V1.0.6 任务备注与附件设计

日期：2026-09-14
状态：待用户复核
目标版本：V1.0.6

## 1. 目标

为已经创建的主任务和子任务提供可重复编辑的备注，并允许备注携带图片或普通文件。编辑行为不得改变任务创建时间或完成时间；当备注文本或附件发生实际变化时，单独记录最近编辑时间。备注中的 HTTP/HTTPS 链接应可通过系统默认浏览器安全打开。

每个任务最多保存 10 个附件，单个附件不超过 20MB，与 AI 助手当前限制保持一致。附件必须由程序复制到统一运行数据目录，不能依赖原文件继续存在，也不能写入 localStorage。

## 2. 不在本次范围内

- 不提供在线文件同步、云端备份或多人共享。
- 不修改任务标题；优先级仍使用任务卡片上的现有下拉框修改。
- 不实现富文本编辑器、Markdown 编辑器或网页内容抓取。
- 不自动访问备注中的网址，只在用户明确点击后打开。
- 不改变现有创建时间、完成时间、提醒时间和 15 天归档清理规则。

## 3. 用户界面

每张主任务和子任务卡片增加“编辑备注”按钮。点击后打开统一编辑弹窗，弹窗包含当前备注文本、已有附件列表、添加附件按钮、移除附件操作、取消和保存按钮。

图片附件在弹窗和任务卡片备注区域显示克制的小型缩略图；普通文件显示文件名、类型和易读大小。点击附件后使用系统默认程序打开。附件操作失败时显示明确提示，不关闭编辑弹窗，也不丢失用户正在编辑的文字。

任务卡片继续显示“创建”和“完成”时间；发生有效编辑后新增“编辑 YYYY-MM-DD HH:mm”。打开弹窗但未修改、修改后还原原值或直接取消时，不更新时间戳。

备注按纯文本保存和渲染。渲染时识别 `http://` 与 `https://` 地址并生成链接，其余协议保持普通文本。点击链接后通过主进程调用系统默认浏览器，页面自身不直接导航。

## 4. 任务数据结构

现有任务增加两个可选字段：

```js
{
  updatedAt: null,
  attachments: [
    {
      id: "随机附件标识",
      name: "原始文件名.png",
      storageName: "随机存储名.png",
      mimeType: "image/png",
      size: 102400,
      addedAt: 1789372800000
    }
  ]
}
```

任务只保存附件元数据和随机存储名，不保存原始绝对路径。`normalizeTasks` 为 V1.0.5 及更早任务补充 `updatedAt: null` 与 `attachments: []`，并过滤格式错误的附件记录。旧数据首次加载后保持兼容，不重写已有创建时间和完成时间。

只有备注文本或附件集合发生实际变化时才写入新的 `updatedAt`。优先级、置顶、折叠、完成或撤销完成不属于备注编辑，不改变 `updatedAt`。

## 5. 附件存储与生命周期

附件根目录：

```text
%APPDATA%\智能任务管家\运行数据\task-attachments\<任务ID>\
```

文件使用随机标识作为磁盘文件名，并保留安全扩展名。原始文件名仅作为界面元数据。所有磁盘路径都由主进程根据任务 ID 和存储名构造，并通过解析后的绝对路径检查确保结果仍位于附件根目录内。

新增根目录模块 `task-attachment-store.js`，负责限制校验、安全文件名、复制、打开、读取图片预览地址、删除单个附件和清理整个任务目录。复制一组附件时如中途失败，应删除本次已经复制的文件并返回错误，避免产生半完成状态。

删除单个附件时同步删除磁盘文件。删除任务及其子任务、或者 15 天清理机制移除已完成任务时，调用主进程清理对应任务目录。缺失的附件文件不阻止任务加载，界面显示“文件已不存在”，并允许用户移除该失效记录。

## 6. Electron 安全边界

`main.js` 注册以下 IPC 能力，`preload.js` 只暴露最小封装：

- 导入用户在文件选择框中明确选择的文件。
- 打开程序附件目录内的指定文件。
- 获取程序附件目录内图片的本地预览地址。
- 删除指定附件或指定任务的附件目录。
- 使用系统默认浏览器打开经过校验的 HTTP/HTTPS 地址。

主进程再次执行单文件 20MB、每任务 10 个文件的限制，不能只依赖前端校验。任务 ID、附件 ID、存储名和协议都必须验证；拒绝路径穿越、符号链接逃逸、`file:`、`javascript:` 等非 HTTP/HTTPS 地址。错误信息不暴露运行数据目录外的敏感路径。

## 7. 编辑保存流程

1. 用户打开编辑弹窗，界面复制当前备注与附件元数据作为草稿。
2. 新选择文件仅进入待导入列表；移除已有附件仅进入待删除列表。
3. 用户取消时丢弃草稿，不执行文件操作，也不更新时间戳。
4. 用户保存时先校验总数量和大小，再由主进程导入新增文件。
5. 导入全部成功后，由主进程逐项删除用户要求移除的已有附件。
6. 更新任务备注与附件元数据时，只移除磁盘删除成功的记录；删除失败的记录继续保留并提示用户，以便再次清理。
7. 备注文本、成功导入或成功删除任一发生时，更新 `updatedAt` 并同步写入任务存储。
8. 导入失败时主进程回滚本批文件，任务数据保持原样，编辑弹窗继续保留草稿。

## 8. 性能与界面风格

附件内容不写入 localStorage，不参与任务列表签名序列化；任务签名只使用附件元数据，避免大文件拖慢渲染。图片缩略图仅在可见任务或打开的编辑弹窗中加载，限制显示尺寸并使用惰性加载。

视觉延续竹青、墨色、淡金和纸白配色。编辑按钮、附件卡片和链接保持简洁，不引入新的高饱和主色；深浅主题均需有清晰边界、悬停状态和键盘焦点。

## 9. 测试标准

- 任务模型测试：旧任务迁移、附件元数据规范化、有效编辑更新时间、创建/完成时间保持不变。
- 附件存储测试：20MB 边界、10 个数量限制、复制回滚、路径约束、单文件删除和任务目录清理。
- 链接测试：只识别 HTTP/HTTPS，拒绝其他协议并正确处理中文标点后的网址。
- Electron 界面冒烟测试：打开编辑弹窗、保存备注、再次编辑、取消不更新时间、链接渲染、深浅主题可读性。
- 完整执行 `npm test`、`npm run test:ui` 和 `npm run dist`，确认 Windows x64 便携版版本信息为 1.0.6。
