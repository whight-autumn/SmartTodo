# SmartTodo V1.3 周期任务与亮度显示修复设计规格

日期：2026-09-22

状态：已确认

目标版本：V1.3.0

## 1. 背景与目标

SmartTodo 当前仅支持一次性任务。用户需要在保留现有任务添加流程、优先级、置顶、附件、父子任务、提醒和桌面任务笺能力的前提下，为少量需要定期重复的工作增加周期属性。

同时，亮度浮层中的百分比在 `100%` 等三位数状态下发生换行，导致控件错位，需要一并修复并验证不同窗口尺寸与系统缩放比例。

本次设计目标：

1. 默认任务仍为一次性任务，不增加普通任务的操作负担。
2. 允许主任务选择每天、每周、每月或每年重复。
3. 重复任务必须设置首次提醒时间，后续提醒从该时间自动推算。
4. 周期任务完成后，在下一周期重新进入待办。
5. 周期结束时若任务未完成，将上一周期欠项转为新周期主任务下的系统子任务。
6. 保持旧数据、现有筛选、提醒、桌面任务笺和响应式布局兼容。

## 2. 非目标

本版本不包含：

- 自定义“每 N 天”“每隔两周”等复杂规则。
- 一个周期内多次提醒或稍后提醒。
- 工作日、节假日跳过规则。
- Windows 独立后台服务；应用完全退出时不承诺实时通知。
- 为系统生成的欠项子任务再次设置周期。
- 单独的周期任务日历或完成历史页面。

## 3. 方案选择

### 3.1 备选方案

1. **稳定主任务 + 欠项快照子任务（采用）**

   周期主任务保留原 ID，在周期切换时重置状态；仅对未完成周期创建系统子任务。优点是兼容现有置顶、桌面任务笺、附件和 IPC 模型，迁移成本低。

2. **每周期复制一个新的顶层任务**

   历史记录直观，但会产生大量顶层重复项，破坏稳定 ID，并增加桌面任务笺和排序逻辑的复杂度。

3. **模板与任务实例完全分离**

   长期模型最纯粹，但需要重构存储、筛选、编辑、完成和同步流程，超出本次需求范围。

### 3.2 决策

采用方案 1。周期主任务是稳定模板和当前周期实例的合体；未完成周期通过只生成一次的系统子任务留痕。该方案在满足需求的同时，最大限度降低对现有功能的扰动。

## 4. 用户界面

### 4.1 添加任务表单

在现有提醒、优先级、任务类型字段旁增加“重复”选择：

- 不重复（默认）
- 每天
- 每周
- 每月
- 每年

交互规则：

- “不重复”保持现有行为。
- 选择任一重复类型后，提醒时间变为必填。
- 未填写提醒时间时，不创建任务；提醒字段显示错误状态、简短内联提示，并获得焦点。
- 不新增配置弹窗，避免低频功能干扰常规添加流程。
- 周期属性仅允许主任务设置；子任务继承周期主任务的刷新过程，不拥有独立周期，避免父子周期冲突。
- 若用户先选择重复、随后把类型改为子任务，重复值自动恢复为“不重复”，并给出非阻塞提示。
- 表单使用自适应网格：宽屏单行或紧凑排列，窄屏自动换行，不压缩控件文字。

### 4.2 任务卡片

周期主任务显示简洁标签：

- `每天 · 09:00`
- `每周 · 周五 17:30`
- `每月 · 15日 10:00`
- `每年 · 09月28日 09:00`

系统生成的欠项子任务显示“上期未完成”或“连续 N 期未完成”标签，并显示对应周期范围。系统标签不占用任务标题，不影响用户编辑原始主任务。

### 4.3 桌面任务笺

- 周期主任务继续参与现有排序、置顶、到期和提醒展示。
- 系统欠项子任务按普通未完成子任务展示，但带欠项标签。
- 在桌面任务笺完成周期主任务时，仍通过主窗口的权威写入通道执行，保证周期元数据不丢失。

## 5. 数据模型

在现有任务结构上增加可选字段：

```js
recurrence: {
  type: 'none' | 'daily' | 'weekly' | 'monthly' | 'yearly',
  anchorAt: 'ISO local datetime',
  activeCycleKey: 'stable cycle identifier',
  lastRolledAt: 'ISO datetime | null'
}
```

系统生成的欠项子任务增加：

```js
systemMeta: {
  role: 'recurrence-carryover',
  sourceTaskId: 'parent recurring task id',
  sourceCycleKey: 'cycle identifier',
  sourceCycleEndKey: 'optional ending cycle identifier',
  missedCount: 1
}
```

兼容规则：

- 没有 `recurrence` 的旧任务在归一化时视为 `{ type: 'none' }`。
- 未知或损坏的周期类型降级为 `none`，原始任务内容仍保留。
- 系统欠项子任务的 `recurrence.type` 始终为 `none`。
- 正常保存、导入、导出和桌面任务笺快照必须显式保留所需周期字段。
- 不对旧任务执行批量破坏性迁移。

## 6. 周期与凌晨 4 点边界

所有周期均使用本地时间，并以凌晨 4 点作为逻辑日期边界：

- 每天：每日 04:00
- 每周：周一 04:00
- 每月：每月 1 日 04:00
- 每年：每年 1 月 1 日 04:00

周期键通过“本地时间减去 4 小时”后再计算日、周、月、年得到。例如周一 02:00 仍属于上一周周期，周一 04:00 才进入新周。

首次创建周期任务时：

- `anchorAt` 使用用户选择的完整提醒时间。
- `activeCycleKey` 使用 `anchorAt` 所属的逻辑周期，而不是简单使用创建时刻。
- 这样可以避免用户提前设置下一周期提醒时，在首次周期边界被错误地向后多推进一次。

## 7. 提醒时间推算

提醒序列始终从 `anchorAt` 按本地日历推算，不从上一次经过截断的日期继续累加：

- 每天：增加一个自然日，保留时、分。
- 每周：增加七个自然日，保留星期和时、分。
- 每月：增加一个自然月，保留锚点日和时、分。
- 每年：增加一个自然年，保留锚点月、日、时、分。

边界规则：

- 月度锚点为 31 日时，无 31 日的月份使用该月最后一天；后续有 31 日的月份恢复到 31 日。
- 年度锚点为 2 月 29 日时，非闰年使用 2 月 28 日；闰年恢复到 2 月 29 日。
- 不使用固定毫秒数累加，避免跨月和夏令时漂移。

每次提醒的去重键由 `taskId + activeCycleKey + remindTime` 组成。进入新周期后产生新的去重键，上一周期已提醒不会阻止下一周期提醒。

## 8. 周期刷新算法

周期检查在以下时机执行：

1. 应用启动并完成任务加载后。
2. 主窗口或桌面任务笺恢复可见时。
3. 运行过程中抵达下一个 04:00 边界时。
4. 发布桌面任务笺快照前。

检查过程必须幂等：

1. 根据当前本地时间计算当前周期键。
2. 当前周期早于任务的 `activeCycleKey` 时，不处理；任务处于首次提醒前的预备状态。
3. 当前周期等于 `activeCycleKey` 时，不处理。
4. 当前周期晚于 `activeCycleKey` 时，执行周期推进。
5. 只有在周期键成功更新后才保存，重复启动不会为同一旧周期再次创建欠项。

### 8.1 上一周期已完成

- 不生成欠项子任务。
- 主任务重置为未完成，清除 `completedAt`。
- 普通子任务重置为未完成；系统欠项子任务保持其现有状态。
- 保留标题、备注、附件、优先级、置顶和创建信息。
- 根据锚点计算当前周期的提醒时间。

### 8.2 上一周期未完成

- 在主任务下生成一个 `recurrence-carryover` 系统子任务。
- 子任务复制上一周期主任务的标题、备注、附件和优先级快照。
- 子任务不继承置顶，不具有周期，不触发历史提醒风暴。
- 主任务随后按新周期重置，并计算新的提醒时间。
- 现有“完成主任务时完成其后代”的行为继续保留，因此用户可通过完成主任务一并结清欠项。

### 8.3 离线跨越多个周期

为避免日任务在长期未启动后生成大量子任务，连续错过多个边界时采用合并策略：

- 将连续未完成周期合并为一个系统子任务。
- 标题标签显示“连续 N 期未完成”。
- `sourceCycleKey` 与 `sourceCycleEndKey` 记录起止范围，`missedCount` 记录期数。
- 不丢失欠期数量，但不为每一期复制完整任务卡片。

## 9. 完成、筛选与清理

- 周期主任务在当前周期完成后正常进入“已完成”筛选。
- 下一周期刷新后，同一主任务重新进入“进行中”。本版本不新增独立历史列表。
- 系统欠项子任务按现有子任务规则参与完成状态与清理。
- 已完成项目的现有保留和清理策略继续生效。
- 优先级和置顶只由稳定主任务持有并跨周期保留。
- 删除周期主任务时，其普通子任务和系统欠项子任务继续遵循现有级联删除规则。

## 10. 通知与故障处理

- 任务在提醒时间前完成时，不发送该周期提醒。
- 应用在提醒时间后启动时，只补发当前有效提醒一次。
- 历史欠项子任务不补发旧系统通知，以卡片欠项状态承担提醒作用。
- 应用完全退出期间不承诺即时通知；下次启动或恢复时执行补算和单次补发。
- 周期计算失败时，不删除、不覆盖原任务；记录诊断信息并保留当前显示状态。
- 写入失败时不提前改变内存中的周期键，避免出现“界面已推进但磁盘未保存”的不一致。

## 11. 亮度百分比修复

亮度浮层中的百分比输出采用独立固定布局：

- `white-space: nowrap`，禁止 `100%` 拆行。
- 使用不少于 `4ch` 的固定宽度并右对齐。
- 使用等宽数字特性，避免数值变化导致跳动。
- 滑杆和输出值分别占位，不依赖绝对定位相互覆盖。
- 保持现有悬停桥接区域，使鼠标可从按钮平滑移动到浮层。

需验证 `0%`、`10%`、`100%`，以及 Windows 100%、125%、150% 缩放和窄窗口布局。

## 12. 测试要求

### 12.1 单元测试

- 旧任务归一化为一次性任务。
- 每天、每周、每月、每年的周期键与提醒推算。
- 凌晨 04:00 前后边界。
- 周一、月初和年初边界。
- 29、30、31 日月末处理及闰年处理。
- 首次提醒在未来周期时不会提前推进。
- 已完成任务刷新时不生成欠项。
- 未完成任务只生成一次系统欠项。
- 离线跨多周期时正确合并并记录 `missedCount`。
- 普通子任务重置，系统欠项子任务不被错误重置。
- 优先级、置顶、备注和附件在刷新后保留。
- 提醒去重键随周期变化。

### 12.2 集成与 UI 测试

- 重复任务未填写提醒时间时阻止提交并给出可见反馈。
- 从主任务切换为子任务时清除周期属性。
- 主界面和桌面任务笺完成周期任务的数据一致性。
- 周期标签、欠项标签和不同长度数据不挤压操作区。
- 亮度值在 `100%` 时保持单行。
- 现有响应式视口矩阵和不同缩放比例下无撕裂、遮挡和异常滚动。
- 全量现有测试无回归。

## 14. 验收标准

1. 一次性任务行为与 V1.2.2 一致。
2. 重复任务没有提醒时间时无法新增，并获得清晰操作反馈。
3. 四种周期均按规定的凌晨 4 点边界刷新。
4. 下一次提醒严格从初始提醒锚点按自然日历推算。
5. 已完成周期不会产生欠项；未完成周期只产生一个幂等欠项记录。
6. 离线跨周期不会产生通知风暴或无限任务卡片。
7. 周期刷新后优先级、置顶、附件、备注和正常子任务保持有效。
8. 主界面和桌面任务笺显示及完成状态一致。
9. 亮度 `100%` 不换行，不在支持的窗口尺寸和缩放比例下错位。
10. 所有自动化测试通过，V1.3.0 产物可启动且版本信息正确。
