# SmartTodo V1.4 设置中心与运行数据迁移设计规格

日期：2026-10-13

状态：设计已确认，待书面规格复核

目标版本：V1.4.0

## 1. 背景与目标

SmartTodo 当前把 AI 服务配置放在“知行助手设置”弹窗中，运行数据固定保存在 `%APPDATA%\SmartTodo\运行数据`，也没有开机自启开关。用户需要一个与现有现代新中式界面完全一致的统一设置入口，并在不损坏既有任务、会话、附件和偏好的前提下完成以下能力：

1. 开启或关闭 Windows 开机自启。
2. 集中配置 AI 服务商、API 地址、模型名称和 API Key。
3. 查看当前运行数据位置，并把完整运行数据迁移到用户选择的新目录。
4. 更换目录后自动重启并从新目录继续工作；失败时可靠回退到旧目录。
5. 完成后升级到 V1.4.0 并更新相关说明文件，但在用户核查通过前不打包、不推送 GitHub。

本次工作的首要约束是数据安全。界面美观和交互效率必须建立在迁移可验证、失败可恢复以及 Electron 安全边界不退化的基础上。

## 2. 非目标

本版本不包含：

- 云同步、账号系统或多设备数据迁移。
- 在多个数据目录之间实时同步。
- 自动清理迁移后的回退副本。
- 用户选择具体单个数据文件或分别设置任务、附件、会话目录。
- 修改可执行文件本身的安装或存放位置。
- 新增 AI 服务商、模型发现、余额查询或 API Key 在线验证。
- 在用户核查前生成发布包、发布 Release 或推送 GitHub。

“程序文件存储位置”在本规格中明确指 SmartTodo 的完整运行数据目录，包括 Chromium 本地存储、任务、AI 会话、AI 配置、附件、桌面任务笺偏好以及同目录中的其他运行时文件，不包括程序可执行文件。

## 3. 方案选择

### 3.1 界面方案

1. **统一设置中心（采用）**

   将现有 AI 设置弹窗扩展为含“常规”“知行助手”“数据存储”三个模块的设置中心。主界面齿轮打开“常规”，助手内的设置按钮直接打开“知行助手”。该方案保留既有入口和弹窗交互，新增功能集中且易于扩展。

2. **独立设置窗口**

   空间充裕，但会引入新的窗口生命周期、焦点、主题同步和多窗口状态管理，对当前三个模块过重。

3. **单页折叠设置**

   实现简单，但模块边界、键盘导航和迁移状态展示较弱，后续扩展容易形成长表单。

采用方案 1。

### 3.2 数据迁移方案

1. **启动前两阶段迁移（采用）**

   当前进程记录迁移请求并自动重启；新进程在设置 `userData`、创建窗口和打开 Chromium 存储之前完成复制、校验和切换。这样可以避开 LevelDB、附件和偏好文件被占用的问题。

2. **程序运行时直接复制并切换**

   表面更即时，但 Chromium 本地存储可能仍持有文件句柄，难以保证得到一致快照，也无法在当前进程中安全更改 `userData`。

3. **只导出业务 JSON 和附件**

   可以避开 Chromium 文件，但容易遗漏未来新增的运行文件，也不符合“迁移所有文件”的要求。

采用方案 1。

## 4. 设置中心界面

### 4.1 视觉与布局

设置中心属于现有操作型界面的自然延伸，不创建新的视觉世界：

- 延续暖宣纸、抬纸、近墨、沉玉绿、朱砂和陈金语义色。
- 标题使用本地 Noto Serif SC，字段、说明和控件使用现有无衬线字体栈。
- 使用现有 6px 控件圆角、14px 容器圆角、1px 细线和对话框环境阴影。
- 玉色只用于当前模块、主操作和成功状态；迁移风险与错误同时使用朱砂和文字说明。
- 不使用新的装饰图片、营销式大标题、夸张卡片或与主工作台冲突的动效。

宽度充足时，对话框采用左侧模块导航与右侧内容区。窄于 640px 时，导航切换为顶部可横向容纳的模块选择，字段纵向排列。对话框保持最大高度约束，内容区独立滚动，页头和底部操作始终可达。

所有模块需支持键盘导航、清晰焦点状态、语义化标签、屏幕阅读器名称和 `prefers-reduced-motion`。

### 4.2 入口规则

- 顶部全局齿轮打开设置中心的“常规”模块。
- 知行助手区域的“设置”按钮打开“知行助手”模块。
- 关闭后焦点返回触发设置中心的按钮。
- 再次打开时保留本次会话中最后访问的模块；不同入口的显式目标优先。

### 4.3 常规模块

常规模块提供“开机时启动 SmartTodo”开关，并显示简短说明：启用后应用在登录 Windows 时后台启动并进入系统托盘，不主动抢占主窗口焦点。

交互规则：

- 打开设置时从主进程读取系统实际状态，不仅依赖前端缓存。
- 切换后调用主进程设置 Windows 登录启动项，再次回读确认。
- 成功时更新开关和状态文字；失败时恢复原状态并显示内联错误。
- 非 Windows 平台显示不可用说明并禁用开关，便于开发和测试环境保持确定行为。

### 4.4 知行助手模块

保留现有字段和兼容行为：

- AI 服务商：DeepSeek、OpenAI、自定义 OpenAI-compatible 服务。
- API 地址。
- 模型名称。
- API Key。

API Key 默认遮蔽，提供带可访问名称的显示/隐藏按钮。保存时继续使用现有 `ai_provider_config` 与 `deepseek_api_key` 键名，避免旧数据迁移和调用逻辑回归。本版本不改变密钥的存储机制；说明文案继续明确配置仅保存在本机运行数据中。

服务商切换继续填充预设地址和模型。自定义服务仍要求有效地址、模型名称和非空 API Key。保存成功后不关闭整个设置中心，显示非阻塞成功状态，便于用户核查。

### 4.5 数据存储模块

数据存储模块展示：

- 当前运行数据目录的完整路径。
- 当前目录是否为默认位置。
- “选择新位置”次操作。
- 选择后的目标完整路径。
- “迁移并重启”主操作。
- 迁移会重启程序、旧目录会保留为回退副本的明确说明。

用户通过 Electron 原生目录选择器选择目标目录。所选目录就是新的运行数据根目录，不再隐式追加子目录，界面必须在确认前显示最终路径。

目标目录必须满足：

- 是绝对路径，且不是符号链接或其他路径重定向。
- 不等于当前目录。
- 不位于当前目录内部，当前目录也不位于目标目录内部。
- 不等于文件系统根目录、用户主目录或工作区等过宽目录。
- 目标不存在时可以创建；目标已存在时必须为空，或只含由本次失败迁移留下且可安全识别的暂存目录。
- 当前进程具有创建、写入、重命名和读取权限。

渲染进程只发起“选择目录”和“确认迁移”意图；实际路径由主进程的原生选择结果产生。预加载桥不得暴露通用文件系统 API。

## 5. 持久化与启动引导

当前默认运行目录保持：

```text
%APPDATA%\SmartTodo\运行数据
```

新增一个不随运行数据迁移的轻量引导文件：

```text
%APPDATA%\SmartTodo\bootstrap.json
```

该文件只保存：

- 当前生效的运行数据绝对路径。
- 待执行迁移的源路径和目标路径。
- 迁移请求 ID 与创建时间。
- 最近一次迁移结果的有限状态与可展示错误，不保存 API Key 或业务内容。

程序启动时在 `app.setPath("userData", ...)` 之前读取并严格校验该文件。文件缺失、损坏或路径不安全时回退到默认目录，并记录可展示诊断信息，不删除任何数据。

写入引导文件使用同目录临时文件加原子重命名，避免断电或进程中止产生半截 JSON。

## 6. 迁移流程

### 6.1 发起阶段

1. 用户选择目标目录。
2. 主进程验证源路径、目标路径、权限和空目录要求。
3. 用户点击“迁移并重启”，设置中心显示不可取消的准备状态并禁用相关控件。
4. 主进程要求主窗口刷新本地状态，调用 Chromium 存储刷新，并让桌面任务笺立即写入位置偏好。
5. 主进程把待迁移记录原子写入 `bootstrap.json`。
6. 调用 `app.relaunch()`，随后正常退出当前实例。

如果写入待迁移记录失败，不退出程序，也不改变当前目录。

### 6.2 启动前执行阶段

新实例启动后、设置 `userData` 之前：

1. 读取待迁移记录并重新验证所有路径。
2. 在目标目录同级创建带请求 ID 的暂存目录，避免把半成品暴露为正式数据目录。
3. 递归复制当前运行数据目录的全部普通目录和普通文件；遇到符号链接、设备文件或路径越界立即失败。
4. 为源目录和暂存目录建立清单，记录相对路径、文件大小和 SHA-256。
5. 比较两份清单，只有相对路径、大小和摘要全部一致才通过校验。
6. 若用户选择的是已存在的空目录，再次确认其仍为空后删除该空目录；随后将暂存目录原子重命名为目标目录。
7. 更新引导文件中的生效路径并清除待迁移记录。
8. 将旧运行数据目录重命名为同级的 `<原目录名>.backup-YYYYMMDD-HHMMSS`；若重命名失败，保留原目录并记录提示，但不影响已验证的新目录启用。
9. 调用 `app.setPath("userData", 新目录)`，继续正常创建窗口、附件存储和桌面任务笺。

迁移清单只用于校验，不作为长期业务数据保留。目标目录最终不包含迁移暂存文件。

### 6.3 失败恢复

任一步骤失败时：

- 不更新当前生效路径。
- 删除本次请求对应且已验证位于目标父目录内的暂存目录；无法安全删除时保留并在错误信息中标明。
- 清除待迁移状态，记录失败摘要。
- 继续用旧运行数据目录启动应用。
- 主窗口启动后显示持久、可读的失败提示，并在数据存储模块提供错误详情和重新选择入口。

不得覆盖非空目标目录，不得删除未被本次迁移请求明确创建的路径，不得自动删除回退副本。

### 6.4 成功反馈

新目录成功启动后：

- 主窗口显示“运行数据已迁移”的成功提示。
- 数据存储模块展示新路径和旧回退副本路径。
- 消费成功状态后清除一次性提示，但保留当前生效路径。
- 用户可自行核查旧副本；本版本不提供自动删除按钮。

## 7. 主进程与安全边界

新增聚焦模块分别负责：

- 引导配置读取、验证和原子写入。
- 运行数据路径解析与迁移。
- Windows 登录启动状态读取和设置。
- 设置相关 IPC 注册与输入验证。

主进程仍是文件系统和操作系统能力的唯一权威。预加载层只暴露固定用途的方法，例如读取设置快照、设置开机自启、选择存储目录、请求迁移和消费迁移结果。每个 IPC 负载使用精确字段校验，不接受渲染进程提供的任意通道名或通用路径操作。

现有 `contextIsolation: true` 与 `nodeIntegration: false` 保持不变。附件存储在启动时根据最终 `userData` 目录构造，迁移后不允许继续持有旧根目录引用。

## 8. 数据与兼容性

- 保留全部既有 `localStorage` 键名和数据结构。
- 保留 `task-attachments` 目录结构和附件相对引用。
- 保留 `widget-preferences.json` 及桌面任务笺可见性和位置。
- V1.0.7 至 V1.3.1 的历史目录自动迁移逻辑继续生效；路径解析顺序为：安全且有效的自定义路径、当前默认路径、历史产品路径。
- 从历史版本首次升级且同时存在自定义引导文件时，不覆盖自定义目录。
- 默认路径展示为当前默认位置；用户迁移回默认路径时使用同一套迁移、校验和回退流程。
- API Key、任务、会话和附件在迁移后必须与迁移前一致。

## 9. 错误与状态文案

界面区分以下状态：

- 当前目录可用。
- 已选择新目录，等待确认。
- 正在准备重启。
- 上次迁移成功。
- 上次迁移失败，仍使用原目录。
- 开机自启设置失败。
- AI 配置字段无效或保存失败。

颜色不能单独承担状态含义。所有错误同时包含简短标题、可理解原因和下一步操作。原始系统错误可被归纳后展示，但不得包含 API Key、会话内容或其他敏感数据。

## 10. 动效与交互细节

- 模块切换采用轻微淡入与 4–8px 位移，沿用现有动效控制器。
- 开关状态、保存反馈和路径选择使用 120–240ms 的颜色、边框与透明度过渡。
- “迁移并重启”点击后立即进入忙碌状态，防止重复请求。
- 尊重 `prefers-reduced-motion`，取消非必要位移。
- 不引入滚动绑定位移、持续背景动画或影响设置效率的展示型动效。

## 11. 测试要求

### 11.1 单元测试

- 默认路径和自定义路径解析。
- 引导文件缺失、损坏、非法路径和原子写入。
- 同路径、嵌套路径、根目录、用户主目录、非空目标和符号链接拒绝。
- 全量复制与 SHA-256 清单一致性。
- 迁移成功时切换目标并生成回退副本。
- 复制失败、校验失败、重命名失败和引导写入失败时继续使用旧目录。
- 历史目录迁移与自定义目录的优先级。
- Windows 登录启动状态读取、启用、禁用和系统调用失败。
- 设置 IPC 的精确负载验证与错误归一化。
- 预加载层不暴露通用文件系统、任意 IPC 或任意路径 API。

### 11.2 集成与 UI 测试

- 两个设置入口打开正确模块并在关闭后恢复焦点。
- 开机自启开关从系统状态初始化，成功和失败状态均正确。
- 服务商预设、API Key 遮蔽切换、字段验证和保存兼容现有配置。
- 当前路径、默认状态、新路径和迁移警告显示正确。
- 迁移忙碌状态阻止重复提交。
- 启动后迁移成功或失败提示只消费一次。
- 键盘可访问模块导航、开关、密码显示按钮、目录选择和保存操作。
- 亮色、深色、1366×768、1920×1080、2560×1440 和较窄窗口下无裁切、不可达操作或横向滚动。
- Windows 100%、125%、150% 显示缩放下文本和控件保持可用。
- 全量现有单元测试、UI smoke、UI layout 和桌面任务笺测试无回归。

## 12. 文件与模块影响

预计新增：

- 引导配置与路径解析模块。
- 运行数据迁移模块。
- 应用设置 IPC 模块。
- 对应单元测试。

预计修改：

- `main.js`：启动前路径解析、迁移执行、登录启动和设置 IPC 接入。
- `main-paths.js`：保留历史兼容，并委托新的路径模块。
- `preload.js`：暴露最小设置桥。
- `renderer/index.html`：把现有 AI 设置弹窗扩展为统一设置中心。
- `renderer/app.js`：模块导航、设置状态、保存和迁移交互。
- `renderer/styles/components.css`、`layout.css`、`motion.css`：设置中心样式、响应式与动效。
- 测试文件：补充安全、迁移、交互和视觉结构覆盖。

保持 `renderer/style.css` 作为样式入口，不把设置逻辑继续堆入不相关模块。若实现阶段发现 `app.js` 的设置职责已经无法独立测试，则提取专用渲染端设置控制器，但不进行与本功能无关的全面重构。

## 13. 版本与文档

功能实现和验证完成后将版本从 V1.3.1 升级为 V1.4.0，并同步更新：

- `package.json` 与 `package-lock.json`。
- 应用标题、预加载版本回退值以及界面中的版本文字。
- `README.md`。
- `CHANGELOG.md`。
- `docs/文件说明.md`。
- `release/版本迭代说明.md`。
- 新增 `release/V1.4.0/版本说明.txt`。
- 与设置中心相关的亮色、深色截图和说明。

完成代码、测试、视觉检查和文档后，先向用户提供变更摘要、测试结果和界面截图。只有收到用户明确核查通过的指令后，才执行 Windows V1.4.0 打包、产物校验、GitHub 提交推送或 Release 操作。

## 14. 验收标准

1. 全局齿轮和知行助手设置入口进入统一设置中心的正确模块。
2. 设置中心在深浅主题、支持窗口尺寸和显示缩放下与现有界面观感一致。
3. 开机自启可启用、禁用并以系统实际状态为准；登录启动不抢占主窗口焦点。
4. 既有 AI 服务商、地址、模型和 API Key 配置保持兼容，API Key 可安全遮蔽与临时显示。
5. 当前运行数据路径和默认状态准确显示。
6. 用户只能通过原生选择器选择新目录，危险路径和非空目标被拒绝并获得清晰反馈。
7. 迁移覆盖当前运行目录中的全部普通文件，复制后通过相对路径、大小和 SHA-256 校验。
8. 迁移成功后自动从新目录启动，任务、会话、设置、附件和桌面任务笺偏好完整可用。
9. 迁移失败时仍从旧目录启动，不覆盖目标已有内容，也不删除用户数据。
