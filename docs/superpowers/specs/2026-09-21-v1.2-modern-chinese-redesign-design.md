# 智能任务管家 V1.2 现代新中式重设计规格

## 1. 目标

将现有 V1.0.7 Electron 桌面应用升级为 V1.2，在不改变任务数据结构、安全边界和既有功能的前提下，建立一套细腻、低调、优雅且具有现代中式气质的完整产品界面。结果应达到可长期维护、可在不同屏幕与高 DPI 环境稳定运行、可作为正式 Windows 桌面产品发布的质量。

正式版本采用标准语义版本 `1.2.0`，产品界面显示 `V1.2`。

## 2. 已确认的产品定位

智能任务管家仍是 Windows 本地优先的个人任务与 AI 助手：无需账号、云同步或团队协作；任务管理离线可用，AI 是用户主动配置的可选增强能力。现有产品事实以根目录 `PRODUCT.md` 为权威记录。

## 3. 设计模式与成功标准

本界面属于 Impeccable 的 Operate 模式。设计服务于持续任务操作，熟悉、可靠和高效优先于展示性效果。

成功标准：

- 首次打开即可理解任务区、筛选、快速创建和 AI 助手的关系。
- 高频任务操作不增加步骤，低频设置和高级字段通过渐进呈现降低噪声。
- 浅色、深色、不同窗口宽度和 Windows 125%／150% 缩放下都不发生重叠、裁切、横向滚动或操作不可达。
- 所有既有功能、数据和附件可直接从 V1.0.7 继续使用。
- 动效能解释状态变化，但不延迟用户进入任务。
- 新图标在应用窗口、程序文件和系统托盘中保持同一品牌识别。
- 桌面任务笺在不置顶、不抢焦点的前提下提供少量重点任务，并与主界面保持单一数据写入边界。

## 4. 视觉方向

### 4.1 世界观

确定的视觉世界为“文人案头／漆夜流萤”。它不是古典元素拼贴，而是把宣纸、黛墨、竹青、朱砂、漆器和微光的材料关系翻译为现代桌面产品语言。

低调奢华来自：

- 准确的比例、留白和信息密度；
- 温润而非纯白／纯黑的底色；
- 克制的色彩数量和明度层次；
- 统一的细线、边界、图标和状态反馈；
- 局部宋体气质与高可读无衬线正文的配合；
- 极轻的纸张颗粒、柔和阴影与不抢内容的材质感。

明确禁止：高饱和渐变、大面积玻璃拟态、霓虹光晕、廉价金色、龙纹祥云堆叠、密集圆角卡片、表情符号操作按钮和无意义装饰动画。

### 4.2 双主题

浅色“文人案头”：

- 温暖宣纸色作为应用背景；
- 黛墨色承担主要文字；
- 竹青承担主操作、选中和焦点；
- 朱砂仅用于危险、逾期和强提醒；
- 哑光铜色只用于少量品牌分隔与非交互细节。

深色“漆夜流萤”：

- 带青调的漆黑作为背景，不使用纯黑；
- 象牙白和低饱和灰绿承担文字层级；
- 玉石绿承担主操作和焦点；
- 暗朱砂与琥珀色分别承担危险和提醒；
- 阴影以层间明度差为主，不使用外发光。

两套主题共享相同语义令牌，亮度滑杆继续作用于基础表面，不改变状态色语义。

### 4.3 字体

- 产品名和少量一级标题使用本地打包的开源中文宋体，形成文化气质。
- 正文、表单、按钮、任务信息、数据和 AI 对话使用现代中文无衬线字体栈。
- 不从远程字体服务加载资源，离线环境必须稳定。
- 产品界面使用固定 `rem` 字阶和明确断点，不使用随容器任意缩放的流体大标题。

## 5. 品牌与图标系统

保留“竹叶与流萤”的品牌记忆，重绘为简洁的矢量母版：

- 两片竹叶形成未闭合的圆弧，表达守护、循环与任务完成；
- 一枚光点和两笔翅形构成流萤，避免写实细节；
- 主版使用宣纸底、墨绿主体和低亮琥珀光点；
- 深色托盘版与小尺寸版采用单色轮廓，保证 16–32px 清晰度；
- 从同一 SVG 母版输出 `icon.png`、`icon.ico`、界面品牌标识和托盘资源。

应用内操作图标采用统一的细线 SVG 语言。图标必须带可访问名称或与可见文字配合，不使用表情符号作为关键操作的唯一表达。

## 6. 信息架构与首屏

### 6.1 应用壳层

顶部为克制的品牌栏：左侧是图标、产品名、归属与 `V1.2`；右侧是亮度、主题和全局入口。顶栏不承担任务统计，避免品牌与工作信息竞争。

主体为“主工作台 + 知行侧席”：

- 宽屏下任务工作台约占 62%，AI 侧席约占 38%；
- AI 收起时变为可识别的窄侧栏，任务区占据剩余空间；
- 中等宽度下两栏比例收紧；
- 窄窗口下 AI 侧席移动到任务区下方或以明确的展开区呈现。

首屏必须直接呈现快速创建、任务筛选、至少一段任务内容与 AI 入口。用户不需要经过欢迎页、引导页或展示性动画才能开始工作。

### 6.2 快速创建

- 标题输入和主操作始终最突出。
- 备注、提醒、优先级、类型和父任务属于次级控制，使用结构化的第二行或渐进展开区。
- 子任务选择仅在类型为子任务时出现。
- 草稿恢复、回车与中文输入法行为保持现状。

### 6.3 筛选与任务列表

- “需关注／进行中／已完成”使用统一分段控件，保留数量。
- 列表减少卡片套卡片，采用有纸张层次的分组行与细分隔。
- 主任务形成章节，子任务通过缩进、连接线和层级间距表达归属。
- 优先级、置顶、逾期、提醒和任务类型同时使用文字／形状／色彩，不只依赖颜色。
- 行操作在悬停、键盘聚焦或选中时显现；关键完成控件始终可识别。
- 已完成内容降低视觉权重，但保留撤销、备注、附件和时间信息。
- 空状态说明如何开始，不只显示“暂无内容”。

### 6.4 AI 知行侧席

- 保留新建会话、清理历史、设置、收合、附件、任务分析和发送。
- 对话区与输入区使用清晰的内容层级，不模拟社交软件气泡堆叠。
- AI 流式输出、错误、思考、禁用和附件状态必须有稳定占位，避免布局跳动。
- 收起状态保留入口和未完成状态提示，不将能力完全隐藏。

### 6.5 对话框与通知

- 任务备注与附件编辑采用纸笺式中宽对话框，正文区可滚动，操作区稳定贴底。
- 设置对话框使用分组字段和清晰说明，不增加额外步骤。
- 删除确认保持明确危险层级和键盘焦点管理。
- Toast 不遮挡主要控件，同类消息合并或顺序排列。

### 6.6 桌面任务笺

V1.2 新增一个独立的轻量 Electron 窗口“桌面任务笺”，作为主界面的补充视图而非第二套任务管理器。

窗口行为：

- 使用无系统边框、透明背景的独立 `BrowserWindow`，默认约为 320×440；内容最小尺寸以真实窗口验证结果为准。
- `alwaysOnTop` 固定为 `false`，其他应用窗口可以自然遮住它；不实现桌面图标层嵌入或强制置顶。
- 默认跳过任务栏和独立 Alt+Tab 入口，通过主界面与托盘菜单控制显示或隐藏。
- 首次运行定位于当前主显示器工作区右侧，使用不抢焦点的方式显示；用户拖动后记忆位置。
- 显示器、工作区、分辨率或 DPI 变化后，将保存位置校正到当前可视工作区，不能让标题栏或操作区落到屏幕外。
- 关闭按钮只隐藏任务笺，不退出应用；主界面隐藏到托盘后，任务笺可继续留在桌面。

内容和交互：

- 顶部显示统一的竹叶流萤小标、日期和待留意数量；顶部非交互留白区域可拖动窗口。
- 最多显示 5 项未完成任务，按“已逾期、24 小时内到期、已置顶、高优先级、其他任务”的顺序选取；同级沿用主任务模型的稳定排序。
- 每项只显示完成控件、最多两行标题、文字化优先级和短提醒；子任务增加一行精简的主任务归属。
- 勾选完成后先请求主界面执行现有完成流程，保存成功才更新任务笺；失败时恢复控件并显示简短错误。
- 底部只提供“打开主界面”和“隐藏任务笺”，不提供创建、编辑、删除、附件或 AI 功能。
- 没有候选任务时显示安静的空状态；同步尚未完成时使用稳定占位，不以无限旋转图标打断用户。

视觉与动效：

- 浅色使用暖宣纸半透明表面，深色使用柔和漆黑半透明表面；颜色、边界、字体、图标、焦点和状态令牌与主界面同源。
- 系统透明合成不可用或会影响可读性时，自动退化为高不透明度实体表面，关键文字继续满足对比度目标。
- 完成任务采用约 180ms 的淡出与收拢，下一任务补位；其他状态变化控制在 150–220ms。
- `prefers-reduced-motion: reduce` 下取消位移和编排，仅保留即时状态或短淡化。

## 7. 响应式与抗撕裂规则

布局按结构断点重排，不通过整体缩放适配：

- `>= 1280px`：稳定双栏，保持 62/38 左右比例并限制两侧最小宽度。
- `1024–1279px`：缩减辅助留白和非必要说明，两栏继续存在但任务区优先。
- `800–1023px`：任务区单列，AI 侧席移至下方可展开区域。
- `< 800px`：表单字段分行、工具栏换行、附件网格缩列、对话框贴近视口边界并允许内部滚动。

实现规则：

- 使用 Grid/Flex、`minmax()`、`auto-fit`、`min-width: 0` 和明确断点；
- 不使用 `transform: scale()`、固定像素画布或绝对定位拼接主布局；
- 长标题、备注和 URL 允许断词换行；文件名和紧凑元信息使用可访问的省略策略；
- 操作栏可以换行但不能覆盖正文；
- 对话框使用视口约束和 `max-height`，标题与底部操作不可滚出视野；
- 不允许应用级横向滚动条。

验收尺寸包括 1366×768、1440×900、1920×1080、2560×1440，以及 Windows 125%／150% 显示缩放。Electron 最小窗口尺寸在实现阶段根据 800px 结构断点调整，但不得小于保证所有操作可达的验证结果。

桌面任务笺单独遵守以下规则：

- 基于 Electron `screen` 返回的 `workArea` 定位，不使用写死的桌面分辨率；右侧默认间距来自共享布局令牌。
- 保存窗口边界时记录其所属显示器；恢复时若显示器不存在，则回到当前主显示器右侧。
- 在 100%、125% 和 150% 缩放下验证文字、拖动区、任务行和底部操作完整，不通过缩放整个页面适配。
- 任务标题、主任务归属和提醒文字必须使用明确的换行／省略规则，不能撑宽透明窗口或形成水平滚动。

## 8. 动效系统

动效只解释状态，不承担装饰：

- AI 侧席展开／收起：约 220ms，使用宽度、透明度和小幅位移组合；
- 任务新增、筛选、排序、完成与撤销：使用 GSAP 进行轻微位移、淡化和位置重排；
- 对话框与 Toast：160–200ms 淡入和小幅上移；
- 图标悬停：轻微颜色和线宽变化，不缩放跳跃；
- 页面加载不播放编排式入场动画。

GSAP 作为本地依赖使用，只负责增强效果。内容默认可见，动效模块失败时所有功能仍可操作。`prefers-reduced-motion: reduce` 下取消位移与编排，改为即时状态或短淡化。

## 9. 功能与数据兼容

以下边界不可因重设计改变：

- 保留所有现有 DOM 行为所需的标识或同步更新对应测试；
- 不修改现有 `localStorage` 键名和任务数据结构；
- 不改变任务排序、关注筛选、完成清理和时间戳语义；
- 不改变附件准备／持久化／提交／回滚事务顺序；
- 不扩大 preload 或 IPC 暴露面；
- 不降低 HTTP/HTTPS 外链限制、文件类型和路径校验；
- AI Provider 请求协议和 API Key 存储方式保持兼容。

桌面任务笺的数据边界：

- 主界面渲染进程继续是任务数据的唯一写入方；任务笺不得直接写入 `smart_tasks`。
- 主界面在任务保存成功后发布经过裁剪的只读快照；快照只包含展示与排序需要的任务字段、父任务标题、主题和亮度，主进程只负责在两个窗口间转发和缓存最后一次快照。
- 任务笺完成操作只允许固定的 `toggle-complete` 动作与任务 ID；主界面复用现有完成、持久化、通知和重绘流程。
- 新增 IPC 必须逐通道注册、校验精确负载并验证发送方窗口；不得暴露任意通道、文件系统、`ipcRenderer` 或任务数据写入接口。
- 任务笺的显示偏好与窗口位置保存在应用运行数据目录的独立小型偏好文件中；损坏、缺失或越界时恢复安全默认值，不影响任务数据。

## 10. 代码组织

在不重构无关业务逻辑的前提下，改善渲染层职责：

- `renderer/index.html`：重组语义布局并尽量保留既有 ID。
- `renderer/style.css`：保留为统一入口，只负责引入 `styles/tokens.css`、`styles/base.css`、`styles/layout.css`、`styles/components.css` 和 `styles/motion.css`；每个文件分别承担主题令牌、基础元素、响应式结构、组件状态和动效降级。
- 新增统一 SVG 图标资源／精灵和品牌图标母版。
- 新增独立动效模块，封装 GSAP 检测、任务变化与面板收合；业务逻辑只调用明确接口。
- `renderer/app.js`：只做连接新结构和动效所需的最小修改，不借机重写任务、附件或 AI 模块。
- `renderer/widget.html`、`renderer/widget.css` 和 `renderer/widget.js`：承担桌面任务笺的语义结构、共享令牌适配与受限交互。
- `renderer/widget-model.js`：使用纯函数完成候选任务选择、稳定排序、短提醒和展示快照归一化。
- `widget-preload.js`：只暴露快照订阅、完成请求、打开主界面和隐藏任务笺四类固定能力。
- `widget-controller.js`：管理任务笺生命周期、位置偏好、工作区校正、托盘入口和窗口间消息路由。
- `main.js`：组合主窗口与任务笺控制器，并更新托盘菜单；窗口细节不继续堆入主入口文件。

任何依赖必须本地打包，不允许运行时从 CDN 获取。

## 11. 组件状态与可访问性

按钮、输入、分段控件、任务行、附件、对话框和 AI 输入均需定义默认、悬停、聚焦、按下、选中、禁用、加载和错误状态。焦点样式不能被阴影或 `overflow` 裁切。

验收要求：

- 使用键盘可完成创建任务、筛选、完成／撤销、打开备注、保存／取消、操作附件、打开设置和发送 AI 消息；
- 对话框打开后焦点进入，关闭后返回触发控件；
- 文字和关键控件达到 WCAG AA 对比度目标；
- 重要状态不只依赖颜色；
- 触控／指针目标具有足够尺寸；
- 减少动态效果偏好生效；
- 中文输入法组合输入不会误触发发送或提交。

## 12. 视觉稿优先工作流

本项目已确认采用 comp-first：

1. 先制作覆盖 1440×900 主界面首屏的完整视觉基准，并为选定方向制作一张与其并列展示的 320×440 桌面任务笺视觉稿；使用真实产品名称和现有功能文案，不虚构商业数据。
2. 视觉稿必须展示浅色“文人案头”主视图，并明确深色“漆夜流萤”的令牌对应关系；图标母版与界面同源。
3. 实现首屏后进行一次对照校准，再扩展完整状态、响应式和深色主题。
4. 最终截图在相同尺寸与多尺寸矩阵下验证，视觉稿是方向和构图基准，但功能完整性与可访问性可要求实现做必要修正。

## 13. 测试与质量门槛

### 13.1 自动化

- 现有 67 项单元测试必须保持 0 失败；环境不支持符号链接时允许原有 2 项按既定条件跳过。
- 扩充真实窗口冒烟测试，覆盖新版 DOM、深浅主题、任务创建、筛选、任务操作、AI 收合、对话框和附件状态。
- 增加多视口检查，至少覆盖 1366×768、1440×900、1024×768 和一个窄于 1024px 的结构断点。
- 增加长任务标题、长备注、长文件名、十附件边界和空状态的布局断言。
- 验证 `prefers-reduced-motion` 降级和关键对比度。
- 为任务笺增加纯函数、IPC 和真实窗口测试：覆盖候选顺序、五项上限、完成成功／失败、主浮窗同步、显示／隐藏、位置恢复、多显示器回退、长标题、空状态与主题同步。
- 任务笺的真实窗口矩阵至少覆盖 100%、125% 和 150% zoom factor，并确认 `alwaysOnTop` 为关闭状态、窗口不抢焦点且不存在水平溢出。

### 13.2 视觉检查

- 在一轮批量截图中检查浅／深主题和桌面／窄屏，不逐项反复截屏。
- 集中修正后最多进行一轮确认截图。

- 最终审查必须检查原始请求、视觉稿、方向合同、桌面与窄屏截图、检测结果和本规格。

## 16. 风险与处理

- 原生 `app.js` 与单页 DOM 耦合较多：优先保留 ID 和事件边界，分阶段替换结构并用 UI 冒烟测试兜底。
- Electron 真实窗口测试当前缺少本地 Electron 可执行文件：实施前通过项目锁文件安装依赖，再建立视觉基线。
- 中文字体体积可能影响便携包：只使用许可明确、必要字重的本地资源，并记录来源与许可证。
- 新图标在大尺寸美观但托盘不可辨识：从同一母版制作简化小尺寸版本，并在 16px、20px、24px、32px 检查。
- 动效可能造成列表跳动或输入延迟：内容默认可见，GSAP 仅增强状态变化，减少动态效果和失败降级必须可用。
- 透明窗口在不同 Windows 合成环境下表现不一致：使用可读性优先的实体表面回退，并在打包后的便携版中验证阴影、透明度与点击区域。
- 双窗口同时操作可能造成任务覆盖：任务写入只发生在主界面，任务笺通过固定 IPC 请求动作并等待保存结果，不直接维护第二份可写状态。
- 已断开的外接显示器可能留下不可见位置：每次显示任务笺前根据当前 `screen.getAllDisplays()` 校正保存边界。

## 17. 完成定义

只有同时满足以下条件，V1.2 才算完成：

1. 已确认的现代新中式视觉系统完整覆盖浅色、深色、主要组件和状态。
2. 竹叶与流萤图标在应用内、程序文件和托盘保持一致且小尺寸清晰。
3. 所有现有功能和本地数据兼容，无安全边界回退。
4. 验证尺寸和高 DPI 场景无重叠、裁切、横向撕裂或操作不可达。
5. 单元测试、真实窗口测试和构建结果有可复查证据。
6. README、文件说明、CHANGELOG、版本说明、PRODUCT 与 DESIGN 文档同步完成。
7. 最终独立界面审查给出可发布结论，或用户明确接受其列出的剩余问题。
8. 桌面任务笺在主界面、托盘、主题、任务完成和跨屏场景中行为一致，且不置顶、不抢焦点、不扩大任务数据写入边界。
